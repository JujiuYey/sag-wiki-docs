# 快速开始

这份指南用于本地开发。SAG Wiki 由三个独立仓库组成：前端 `sag-wiki-app`、后端 `sag-wiki-server`、文档 `sag-wiki-docs`。需要 PostgreSQL、Redis、MinIO 和 Qdrant 四个基础设施服务。先启动这些服务，再分别启动 Go API 和 React Web。

## 环境要求

- Go 1.25.3+
- Node.js 20.19+ 或 22.12+
- pnpm 10+
- Docker Desktop 或 Docker Engine
- Docker Compose v2+

## 1. 获取项目

SAG Wiki 现在拆分为三个独立仓库，需要分别克隆。建议把它们放在同一个工作目录下：

```bash
mkdir sag-wiki && cd sag-wiki
git clone https://github.com/JujiuYey/sag-wiki-server.git
git clone https://github.com/JujiuYey/sag-wiki-app.git
git clone https://github.com/JujiuYey/sag-wiki-docs.git
```

后续命令假设工作目录布局如下：

```text
sag-wiki/
├── sag-wiki-server/   # Go API
├── sag-wiki-app/      # React Web
└── sag-wiki-docs/     # 文档
```

## 2. 启动本地基础设施

`docker-compose.yml` 不再随任何仓库下发，建议放在工作目录根目录（`sag-wiki/`），便于三个仓库共享同一份基础设施配置。创建 `sag-wiki/docker-compose.yml`，内容如下：

```yaml
services:
  postgres:
    image: postgres:15
    container_name: postgres-server
    restart: always
    ports:
      - "5432:5432"
    environment:
      POSTGRES_PASSWORD: ${POSTGRES_PASSWORD:-local-dev-password}
      POSTGRES_INITDB_ARGS: "--encoding=UTF8 --lc-collate=C --lc-ctype=C"
    volumes:
      - postgres-data:/var/lib/postgresql/data

  minio:
    image: minio/minio
    container_name: minio-server
    restart: always
    ports:
      - "9000:9000"
      - "9090:9090"
    environment:
      MINIO_ROOT_USER: ${MINIO_ROOT_USER:-minioadmin}
      MINIO_ROOT_PASSWORD: ${MINIO_ROOT_PASSWORD:-local-dev-password}
    volumes:
      - minio-data:/data
    command: server /data --console-address ":9090"

  qdrant:
    image: qdrant/qdrant
    container_name: qdrant-server
    restart: always
    ports:
      - "6333:6333"
      - "6334:6334"
    volumes:
      - ./qdrant_storage:/qdrant/storage

  redis:
    image: redis:7
    container_name: redis-server
    restart: always
    ports:
      - "6379:6379"
    volumes:
      - redis-data:/data
    command: redis-server --appendonly yes

volumes:
  postgres-data:
  minio-data:
  redis-data:
```

启动并查看服务状态：

```bash
docker compose up -d
docker compose ps
```

这四个服务的默认地址和用途如下：

| 服务 | 地址 | 用途 |
| --- | --- | --- |
| PostgreSQL | `localhost:5432` | 用户、权限、目录、文档和会话数据 |
| Redis | `localhost:6379` | 异步文档处理和任务队列 |
| MinIO | `localhost:9000` | 原始文档、附件和头像文件 |
| MinIO Console | `localhost:9090` | 查看和管理对象存储 |
| Qdrant | `localhost:6333` | 文档切片和向量检索 |

检查服务是否可用：

```bash
curl http://localhost:6333/collections
curl http://localhost:9000/minio/health/live
docker compose exec redis redis-cli ping
```

如果要自定义本地密码，在 `docker compose up -d` 前设置环境变量：

```bash
export POSTGRES_PASSWORD='your-local-password'
export MINIO_ROOT_USER='minioadmin'
export MINIO_ROOT_PASSWORD='your-local-password'
docker compose up -d
```

## 3. 初始化数据库

迁移文件位于 `sag-wiki-server/migrations/`，在工作目录根目录执行：

```bash
docker compose exec postgres createdb -U postgres sag_wiki
docker compose exec -T postgres psql -U postgres -d sag_wiki < sag-wiki-server/migrations/system/001_schema.sql
docker compose exec -T postgres psql -U postgres -d sag_wiki < sag-wiki-server/migrations/wiki/001_schema.sql
docker compose exec -T postgres psql -U postgres -d sag_wiki < sag-wiki-server/migrations/ai/001_schema.sql
docker compose exec -T postgres psql -U postgres -d sag_wiki < sag-wiki-server/migrations/ai/002_schema.sql
```

如果数据库已经存在，`createdb` 报错时可以忽略，然后继续执行尚未应用的迁移。

## 4. 配置并启动 Go API

```bash
cd sag-wiki-server
cp .env.example .env
```

检查 `sag-wiki-server/.env` 中的基础设施配置：

```dotenv
DB_HOST=localhost
DB_PORT=5432
DB_USER=postgres
DB_PASSWORD=local-dev-password
DB_NAME=sag_wiki
MINIO_ENDPOINT=localhost:9000
MINIO_ACCESS_KEY=minioadmin
MINIO_SECRET_KEY=local-dev-password
QDRANT_URL=http://localhost:6333
REDIS_ADDR=localhost:6379
```

如果启动 Compose 时修改了用户名或密码，这里也要同步修改。然后启动 API：

```bash
go mod download
go run main.go
```

API 默认运行在 `http://localhost:8080`。

## 5. 配置并启动 React 应用

新开一个终端，回到工作目录根目录：

```bash
cd sag-wiki-app
cp .env.example .env
pnpm install
pnpm dev
```

Web 应用默认运行在 `http://localhost:5200`。

## 6. 停止基础设施

```bash
docker compose down
```

这不会删除数据卷。确认要清空本地数据库、对象存储和 Redis 数据时，才使用：

```bash
docker compose down -v
```
